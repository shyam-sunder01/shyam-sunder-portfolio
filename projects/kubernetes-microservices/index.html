Personal Project

Microservices Deployment on Kubernetes

A containerized Java microservices application deployed on Kubernetes using Minikube. The project demonstrates microservice packaging with Maven, Docker image creation, Kubernetes Deployments and Services, service-to-service communication, health checks, and container orchestration.

View on GitHub ← Back to Projects

Overview

Project Overview

This project demonstrates the deployment of a containerized Java microservices application on a Kubernetes cluster running through Minikube.

The application consists of three independently packaged services: Shopfront, Product Catalogue, and Stock Manager.

Each service is built using Maven, packaged as a Java application, containerized using Docker, published to Docker Hub, and deployed to Kubernetes using dedicated Deployments and NodePort Services.

The Shopfront service retrieves product information from the Product Catalogue service and stock information from the Stock Manager service, combining the responses into the application's product view.

Application Flow

Service-to-Service Communication

The Shopfront service uses a Spring RestTemplate to communicate with the backend services.

The Product Repository requests product information from the Product Catalogue service through the /products endpoint.

The Stock Repository requests inventory information from the Stock Manager through the /stocks endpoint.

The Product Service then combines product and stock information to create the application's product representation.

Product Catalogue Provides product information through the /products endpoint.
Stock Manager Provides inventory information through the /stocks endpoint.
Shopfront Aggregation Combines product and inventory data before presenting the resulting product information.

Build

Maven Application Build

Each microservice is maintained as an independent Maven project and packaged into a Java artifact before containerization.

The build process produces the application JAR that is subsequently copied into the corresponding Docker image.

Containerization

Docker Containerization

Each microservice is containerized independently using a dedicated Dockerfile and the Eclipse Temurin Java 8 runtime.

The resulting images are tagged using the Docker Hub account and published before deployment to Kubernetes.

Kubernetes

Kubernetes Deployment

The application is deployed to a Minikube Kubernetes cluster running with the Docker driver.

Each microservice has a Kubernetes Deployment responsible for managing its Pod and a NodePort Service responsible for exposing the application.

The deployments use one replica for each service in the current project configuration.

Workloads

Running Kubernetes Pods

Kubernetes creates a Pod for each deployed microservice. Each Pod contains the corresponding application container created from the Docker image.

Networking

Kubernetes Services

Each application component is exposed through a Kubernetes NodePort Service. The Services select their corresponding Pods using application labels.

Shopfront Service NodePort Service targeting the shopfront application on port 8010.
Product Catalogue Service NodePort Service targeting the productcatalogue application on port 8020.
Stock Manager Service NodePort Service targeting the stockmanager application on port 8030.

Reliability

Application Health Checks

Kubernetes liveness probes are configured for the application containers to allow Kubernetes to monitor application health.

The Shopfront and Stock Manager services expose health endpoints through their application configuration, while the Product Catalogue uses its Dropwizard administration endpoint for health monitoring.

Monitoring

Kubernetes Dashboard

The Minikube Dashboard was used to inspect Kubernetes workloads, Pods, Services and application status through a graphical interface.

Result

Application Running on Kubernetes

After the Docker images were published and the Kubernetes resources applied, the microservices were available through their configured Kubernetes Services.

The deployed application was validated through the exposed Shopfront service and Kubernetes workload status.

Engineering

Key Concepts Demonstrated

Containerization

Packaged each Java microservice into an independent Docker image using a Java runtime container.

Kubernetes Deployments

Used Deployments to manage application Pods and declaratively define the desired workload state.

Kubernetes Services

Used NodePort Services to expose the individual application workloads.

Service Communication

Shopfront retrieves product and stock information from the backend microservices.

Health Monitoring

Configured Kubernetes liveness probes to monitor application health.

Fault Tolerance

Implemented a Hystrix fallback in the Stock Manager integration path for unavailable stock responses.

Engineering Learnings

Next Steps
